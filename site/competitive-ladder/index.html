Compose the services that make competitive play possible: identities, admission, matchmaking, game hosting, authoritative results, ratings, and history. StarCraft II is the first recognizable workload—not the product ServerApp is becoming.

The goal is to prove that ServerApp can host a complete competitive system assembled from independent capabilities, then extend that same model beyond 1v1.

Interactive architecture modelOne platform. Many game systems.

ServerApp provides the hosting and operational boundary. FSM_COS composes approved bot runtimes. Foundry coordinates execution lifecycle. A game adapter connects an external game engine. Creators keep ownership of their bots.

Ownership boundaries

Each layer has a job.

Do not collapse the ladder, the game, the bot runtime, and the host into one StarCraft-specific process. ServerApp is the composition and hosting platform around independently owned workloads.

01 · ServerAppCompetitive services

Identity, admission, queues, match records, ratings, routing, capacity, operations.

02 · FoundryExecution lifecycle

Host-registered workflows, bounded orchestration, cancellation, outcomes.

03 · FSM_COSBot composition

Compose approved MicroBundles into a runtime assembly from a host-supplied catalog.

04 · Game adapterExternal game

Connect the composed match to StarCraft II or another supported game environment.

05 · Bot creatorsIndependent agents

Own strategy, releases, identity, and optional team coordination contracts.

Platform responsibility

ServerApp

Admission policy, matchmaking, authoritative match state, result validation, rating history, resource placement, and role lifecycle.

Execution responsibility

Foundry + FSM_COS

Foundry runs the approved workflow. FSM_COS composes the bot's MicroBundles. Neither becomes the ladder's rating database.

Game responsibility

Game host / adapter

The game environment owns simulation truth. The adapter reports trusted game events and terminal outcomes to the platform.

Creator responsibility

Bot identity

Creators publish versioned bots. A match references immutable bot/build identities; team membership does not erase provenance.

Trust boundary

Result authority

A bot cannot award itself a win. ServerApp records outcomes only from an explicitly trusted game-host result path.

Presentation boundary

GitHub Pages

This site explains and simulates composition. It is not the authoritative queue, database, game host, or public control API.

What this demo proves: the UI can express multiple match formats and show how their participants map to platform-owned services. What it does not prove: live matchmaking, a working StarCraft II adapter, bot execution, authoritative results, ratings, or production hosting. Those require real implementation and evidence.
